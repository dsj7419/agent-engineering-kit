# Security policy

The kit provides instructions and optional local command execution, not a sandbox or an authorization mechanism. Review all configurations, instructions and commands before execution. Run only trusted manifests in isolated, least-privilege development environments. Never run against production data or expose secrets in reports.

## Reporting

Use the repository's **Security → Advisories → Report a vulnerability** private reporting feature if enabled. If unavailable, open a public issue asking for a private contact, without disclosing the vulnerability or sensitive details. Include affected version, reproduction, impact and remediation if known in the private report. Do not post credentials, exploit details or private code publicly. Maintainers should coordinate remediation and disclosure; no response SLA is promised.

## Supported versions

Security fixes are intended for the latest released minor version, subject to maintainer availability. Older releases are not guaranteed maintenance. Repository owners must enable and verify private vulnerability reporting before public launch when available. If unavailable, establish a verified private reporting channel, document it here, and record the exception in the release checklist before publication.
