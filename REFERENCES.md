# Engineering References

These resources inform the engineering approach; the kit's adaptive profile and workflows are local policy decisions, not requirements stated by these sources. See [Standards alignment](docs/engineering/STANDARDS_ALIGNMENT.md) for formal standards and scope limitations.

- Robert C. Martin, [The Clean Architecture](https://blog.cleancoder.com/uncle-bob/2012/08/13/the-clean-architecture.html) — inward dependency direction.
- Martin Fowler, [Refactoring](https://martinfowler.com/books/refactoring.html) and [Bounded Context](https://martinfowler.com/bliki/BoundedContext.html) — behavior preservation and domain boundaries.
- Google, [What to look for in a code review](https://google.github.io/eng-practices/review/reviewer/looking-for.html) and [Small CLs](https://google.github.io/eng-practices/review/developer/small-cls.html) — review quality and small changes.
- OWASP, [Cheat Sheet Series](https://cheatsheetseries.owasp.org/) — secure development guidance.
- NIST, [Secure Software Development Framework](https://csrc.nist.gov/Projects/ssdf) — secure lifecycle.
- OpenAI, [Codex prompting guide](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide) and [Using PLANS.md](https://developers.openai.com/cookbook/articles/codex_exec_plans) — persistent repository instructions and execution plans.
- Anthropic, [Claude Code memory](https://code.claude.com/docs/en/memory) — project instructions and imports.
- Gemini CLI, [GEMINI.md context files](https://geminicli.com/docs/cli/gemini-md/) and [Memory Import Processor](https://geminicli.com/docs/reference/memport/) — shared instruction imports.
